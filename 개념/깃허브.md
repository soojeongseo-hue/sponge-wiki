# 깃허브 (GitHub)

> 한 줄 정의: 파일을 **고친 기록까지 통째로** 인터넷에 보관하고 같이 쓰는 곳

## 내 한 줄 정리
깃허브 : 나만의 노트

---

## 깃(Git)과 깃허브(GitHub)는 다른 거예요

| | 깃 (Git) | 깃허브 (GitHub) |
|---|---|---|
| 정체 | 기록을 남기는 **방식(기술)** | 그 기록을 올려 두는 **인터넷 장소** |
| 비유 | 사진 찍어 앨범에 넣는 **방법** | 앨범을 올려 두는 **인터넷 사진관** |
| 어디에 | 내 컴퓨터 | 인터넷 (github.com) |

**GitHub Desktop** = 깃을 버튼으로 쓰게 해 주는 앱. 명령어를 몰라도 돼요.

---

## 꼭 알아야 할 용어 8개

### 1. 장소

| 용어 | 영어 | 쉽게 말하면 |
|---|---|---|
| 저장소 (레포) | Repository (Repo) | 기록이 남는 **특별한 폴더** = 공책 한 권 |
| 로컬 | Local | **내 컴퓨터**에 있는 것 |
| 원격 (오리진) | Remote (origin) | **인터넷(깃허브)**에 있는 것 |

### 2. 하는 일

| 용어 | 영어 | 쉽게 말하면 | 방향 | GitHub Desktop 버튼 |
|---|---|---|---|---|
| 클론 | Clone | 남의 공책을 **처음 통째로** 내려받기 | 인터넷 → 내 컴퓨터 | File → Clone Repository |
| 커밋 | Commit | 고친 내용에 **이름표 붙여 저장** (사진 한 장 찍기) | 내 컴퓨터 안 | Commit to main |
| 푸시 | Push | 커밋을 인터넷으로 **보내기** | 내 컴퓨터 → 인터넷 | Push origin |
| 풀 | Pull | 남이 올린 새 내용을 **받아오기** | 인터넷 → 내 컴퓨터 | Pull origin |
| 페치 | Fetch | 새 내용이 있는지 **확인만** 하기 | (확인만) | Fetch origin |

### 3. 기타

| 용어 | 쉽게 말하면 |
|---|---|
| 히스토리 (History) | 지금까지 찍은 **사진(커밋) 앨범** — 예전으로 돌아갈 수 있음 |
| 브랜치 (Branch) · main | 공책의 **줄기**. 지금은 기본 줄기 `main` 하나만 쓰면 돼요 |

## 한 장 그림

```
        [인터넷 = 깃허브]
          ▲          │
     푸시 │          │ 풀 / 클론
          │          ▼
        [내 컴퓨터 = 로컬]
              ▲
              │ 커밋 (이름표 붙여 저장)
          파일 고치기
```

## 내가 실제로 하는 순서

| 상황 | 순서 |
|---|---|
| 내 위키 쓸 때 | 파일 고치기 → **커밋** → **푸시** |
| 스폰지클럽 과제 낼 때 | **풀**(남들 것 먼저 받기) → 파일 고치기 → **커밋** → **푸시** |

💡 같이 쓰는 공책(스폰지클럽)은 **먼저 풀**부터! 남이 고친 걸 안 받고 올리면 부딪혀요(충돌).

## 예시
- 11/3 처음 해 봄: `sponge-wiki` 저장소 만들기 → 파일 4개 → "위키 첫 페이지 만들기" 커밋 → 푸시
- 스폰지클럽 저장소(`spongeclub-4`)는 처음에 **클론**해서 받은 것
